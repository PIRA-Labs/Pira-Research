CRITICAL GATE: isSupportThirdPartyApp
---------------------------------------
Location: DeviceModelExtKt / isSupportThirdPartyApp(wearableDeviceModel)

Logic:
  return isSupportFeature(model, Feature.THIRD_PARTY_APP)
      || isSupportFeature(model, Feature.THIRD_PARTY_APP_NO_MARKET)

Where isSupportFeature does:
  List<String> features = deviceModel.getProduct().getFeatures()
  return features != null && features.contains(feature)

Redmi Watch 4 product features (observed):
  Contains: watchface, market, launcher, ...
  Does NOT contain: thirdparty_app, third_party_no_market

Result: isSupportThirdPartyApp(Redmi Watch 4) == false

This is the gate that causes XmsDataHandler.handlePacket(20/6) to return
false BEFORE reaching third-party app handlers. The packet arrives physically
but Mi Fitness discards it at the application layer.

CONCLUSION
----------
The Mi Fitness feature gate is a SOFTWARE POLICY, not a hardware or protocol
limitation. The watch transmits, Bluetooth delivers, and Mi Fitness receives
the packet — but the application-layer capability check prevents delivery to
third-party apps via the public API.
